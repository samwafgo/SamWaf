# 分层缓存与 PostgreSQL 性能基准（2026-11-21）

本页记录缓存阶段快照 `c8d96c7` 的测量。后续 eBPF、封禁批量查询及共享计数改变了请求路径；这些历史数值不作为后续提交的重新测量结果。

安全状态改造后的同条件重测见 [eBPF 与安全状态性能对比](PERFORMANCE-EBPF-SECURITY.zh-CN.md)。

本轮使用本 PR 基于官方 df095c9 的实现，在完成二进制功能验收后进行。12 并发填充锁检查属于功能验证；本文单独记录吞吐与延迟。

## 测试条件

- Debian 13.8，ARM64，2 vCPU、约 12 GiB 内存，PostgreSQL 17.12。
- 被测二进制 SHA256：`544607e33995223dfb4847a52517654c28732ffa00f7d9e2628f9be64e2686db`。
- 发压工具 wrk 4.1.0、临时 Go 源站和 WAF 同机，共享两核；HTTP/1.1 keep-alive，连接数 1/16/64。
- 普通 HTTP 窗口 12 秒，持续 MISS 窗口 8 秒；响应为 4 KiB 或 256 KiB 固定二进制。
- 共 23 个 HTTP 样本、9 个 KV 样本。64 并发的无缓存/L2/L1各跑两轮，表格为各轮指标的中位数；不是合并直方图后的分位数。
- 只有临时测试站点关闭 CC 限流，全局规则未改。检测组保留模板中的检测规则，OWASP 未启用。
- L2 保留操作系统正常页缓存，没有执行全局 drop_caches。命中窗口根盘块读取量为 0，因此不能把这些数字称为冷 SSD 读取性能。

## 4 KiB，64 并发

| 场景 | 请求/秒 | P50 ms | P95 ms | P99 ms | WAF CPU % | PG CPU % | 发压 CPU % | 轮数 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 直连临时源站 | 37,097 | 1.655 | 5.881 | 8.509 | 0.4 | 0.1 | 64.2 | 1 |
| WAF 无缓存／检测关闭 | 4,282 | 14.425 | 32.661 | 41.913 | 140.2 | 0.2 | 17.7 | 2 |
| L2 命中／检测关闭 | 7,810 | 8.875 | 55.466 | 84.378 | 168.7 | 0.1 | 29.3 | 2 |
| L1 命中／检测关闭 | 12,679 | 5.478 | 59.175 | 89.131 | 159.7 | 0.1 | 38.5 | 2 |
| L1＋检测规则，CC 限流关闭 | 1,368 | 45.403 | 67.216 | 79.231 | 71.4 | 119.8 | 7.5 | 1 |

无检测路径中，L1 吞吐约为无缓存的 2.96 倍，L2 约为 1.82 倍。带检测的 L1 约 1,368 请求/秒，不能把关闭检测的 L1 数值作为正常防护吞吐。

CPU 的 100% 表示占满一个逻辑核，整机上限约 200%。带检测场景中 PG 约占 1.2 核，与 WAF 合计接近两核，说明 PostgreSQL 安全状态访问是显著成本。这里只确定组件级资源瓶颈，不声称已经做过函数级 CPU profile。

## 带检测 L1 的并发变化

| 并发 | 请求/秒 | P95 ms | P99 ms |
|---:|---:|---:|---:|
| 1 | 680 | 1.683 | 2.304 |
| 16 | 1,327 | 17.280 | 21.822 |
| 64 | 1,368 | 67.216 | 79.231 |

从 16 增到 64 并发时吞吐基本进入平台区，尾延迟明显增加；提高并发数并不等于获得同比吞吐。高并发下 L1 的尾延迟也未必优于 L2，数据应按饱和状态解读。

## 持续 MISS 与持久填充

4 KiB、16 并发、每请求使用唯一 URI：307 请求/秒，P95 254.9 ms、P99 411.4 ms。完成 2456 个请求，源站记录 2472 次请求（含计时终止时在途请求）。
本轮根盘写入约 183.3 MiB，包含文件系统元数据和其他进程的块写入，不等于 L2 正文字节数。测试站点索引限制为 2048 条，因此该样本后段同时包含回收/替换成本。
持久填充吞吐远低于命中路径，结合较低的 WAF CPU 占用，后续应分析同步提交、文件元数据和索引/租约争用。不能在没有耐久性设计的情况下直接删除同步或完整性检查。

## PostgreSQL KV/TTL 微基准

使用独立临时数据库、普通应用角色、1000 个键、每值 1 KiB 字符串；pgbench 持久连接，每项 8 秒。此测试不包含完整控制台鉴权、响应序列化和传输加密。分位数来自完整事务日志。

| 操作 | 连接 | 事务/秒 | P50 ms | P95 ms | P99 ms | 失败事务 |
|---|---:|---:|---:|---:|---:|---:|
| GET | 1 | 5,052 | 0.193 | 0.230 | 0.254 | 0 |
| GET | 8 | 8,616 | 0.898 | 1.620 | 1.975 | 0 |
| GET | 32 | 7,479 | 4.532 | 9.865 | 12.045 | 0 |
| GETEX | 1 | 968 | 1.007 | 1.255 | 1.403 | 0 |
| GETEX | 8 | 3,349 | 2.276 | 3.612 | 4.545 | 0 |
| GETEX | 32 | 5,380 | 5.631 | 9.456 | 12.407 | 0 |
| SET | 1 | 985 | 0.992 | 1.227 | 1.376 | 0 |
| SET | 8 | 3,324 | 2.272 | 3.590 | 4.527 | 0 |
| SET | 32 | 5,332 | 5.638 | 9.445 | 12.465 | 0 |

GETEX 与 SET 包含持久写入；单连接吞吐明显低于 GET，多连接可通过并行和组提交提高吞吐。没有运行 Redis 对照，不能宣称 PostgreSQL KV 与 Redis 性能等价。

## 稳定性与收尾

HTTP/socket 错误共 0，KV 失败事务共 0。WAF 监督进程与 Worker 的 PSS 合计峰值约 205.2 MiB。
临时站点、源站、测试数据库和缓存目录已经移除。清理热副本后做了受控服务重启，服务 active，自动异常重启数 0；新空闲进程 PSS 约 124.4 MiB。另已复核公网 HTTPS 与管理端加密登录。
本轮不是长时间浸泡、超内存工作集、断电或公网容量/SLA 测试。原始聚合数据和逐轮缓存层计数见 [JSON 数据](performance-tiered-postgres-20261121.json)。原始 wrk/pgbench 运行日志保留在私有验证材料中，未包含在本 PR。

## 优先优化方向

1. 先收敛防护路径每请求的 PostgreSQL 状态往返，评估一次批量查询所需状态，同时保留封禁/撤销即时性和后端故障分类。
2. 分析持续填充的文件同步、元数据写入及索引/租约持有时间，再对照 Nginx 的写入和回收机制调整。
3. 使用独立发压机复测，并加入固定到达率和长时间负载，建立有余量的延迟目标；不要以本轮饱和峰值作为生产承诺。
