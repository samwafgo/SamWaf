# eBPF 与安全状态改造的 HTTP 性能对比（2026-11-21）

本页比较缓存阶段 `c8d96c7` 与执行代码提交 `c24d6c9e46739b18dd9aa46a5c23683095b46da3`。后一提交的源码树为 `97b71e06716adb84866e418eddf0f7db22761ab4`；后续文档和注释整理不改变被测逻辑。原始脱敏样本见 [performance-ebpf-security.json](performance-ebpf-security.json)。

## 测试条件

- 同一 Debian 13.8 ARM64 主机，2 vCPU、约 12 GiB 内存，内核 `6.12.117+deb13-cloud-arm64`，PostgreSQL 17.12。
- wrk 4.1.0、临时 Go 源站与 WAF 同机，HTTP/1.1 keep-alive；每个样本 12 秒。
- 固定 4 KiB 公共响应，预热后命中 L1；保留模板防护规则，OWASP 未启用，仅关闭临时站点的 CC 规则。
- 临时站点使用既有可信代理配置，将回环发压客户端的测试身份映射到基准地址；前后配置相同。测试结束删除站点与源站。
- 16 并发前后各一轮，64 并发前后各两轮。表格为各轮指标的中位数；不是合并直方图后的分位数。只有两轮或一轮，不作为置信区间。
- 计时样本均为零连接/读写/超时/HTTP 状态错误、零源站读取、零 L2 命中；正常 OS 页缓存保持启用。
- 新版 eBPF 程序已加载，测试流量未被封禁；此测试测量完整 HTTP 路径，不测最大封禁包速率。

## 吞吐和延迟

| 并发 | 版本 | 请求/秒 | P95 ms | P99 ms | 轮数 |
|---:|---|---:|---:|---:|---:|
| 16 | 切换前 | 1,332.19 | 17.379 | 22.318 | 1 |
| 16 | 切换后 | 2,411.04 | 11.710 | 15.963 | 1 |
| 64 | 切换前 | 1,298.09 | 70.750 | 84.380 | 2 |
| 64 | 切换后 | 2,088.84 | 49.462 | 62.131 | 2 |

16 并发吞吐约 +81.0%，P95 约 -32.6%。64 并发吞吐约 +60.9%，P95 约 -30.1%。64 并发原始吞吐两轮分别为切换前 1,282.88 / 1,313.31，切换后 2,068.49 / 2,109.19 请求/秒。

本轮四个安全状态键由四次串行查询合成一次查询，但没有缓存负结果；新增/解封仍在 PostgreSQL 提交后可见。性能改善属于这组整体改造，不能只归因于 eBPF。64 并发比 16 并发更慢，说明同机 CPU/数据库争用和尾延迟仍限制扩展。

## 资源占用

CPU 的 100% 表示一个逻辑核，整机理论上限约 200%；数值取自 cgroup 计时窗口。

| 并发 | 版本 | WAF CPU % | PostgreSQL CPU % |
|---:|---|---:|---:|
| 16 | 切换前 | 72.58 | 113.93 |
| 16 | 切换后 | 97.24 | 87.56 |
| 64 | 切换前 | 72.96 | 114.23 |
| 64 | 切换后 | 93.29 | 82.16 |

数据库 CPU 占用下降，WAF 在更高吞吐下 CPU 占用上升。新旧样本的 WAF PSS 峰值分别最高约 179.91 / 167.27 MiB；这是不同进程生命周期与分配热身下的观测值，不能视为单项功能的净内存成本。

计时窗口中 WAF/源站/发压器共享两核，根盘读取为 0。写入包含 PostgreSQL、日志及系统活动，不能直接当作缓存正文写放大。
